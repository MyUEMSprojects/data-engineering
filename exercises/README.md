# Exercícios

Prática **progressiva** para cada módulo do currículo: do conceito ao projeto. Cada módulo tem uma pasta com 6 exercícios em
**dificuldade crescente**, de tipos variados, e o **gabarito** vem recolhido (`<details>`) — **tente antes de abrir**.

## Escala de dificuldade

| Marca | Nível | Você deve conseguir… | Tempo típico |
| --- | --- | --- | --- |
| 🟢 | Básico | explicar o conceito ou escrever uma consulta/script curto | 5–15 min |
| 🔵 | Intermediário | combinar 2–3 conceitos e justificar escolhas | 15–45 min |
| 🟣 | Avançado | projetar, depurar sob restrições ou medir trade-offs | 45 min+ |

## Tipos de exercício

| Tipo | O que treina |
| --- | --- |
| **Conceitual** | explicar com as próprias palavras, comparar, escolher |
| **SQL** | escrever, ler e otimizar consultas (testáveis no DuckDB/PostgreSQL) |
| **Implementação** | escrever código que funciona (Python, shell, YAML, HCL) |
| **Debugging** | achar o defeito num trecho que "quase funciona" |
| **Arquitetura** | desenhar uma solução, defender trade-offs, estimar custos e riscos |

## Como estudar

1. Leia o módulo; faça os exercícios **sem** olhar o gabarito; escreva a resposta (nem que seja em rascunho).
2. Só então abra o gabarito. Se a sua resposta diferir, entenda **por quê** — muitas têm mais de um caminho válido.
3. Os exercícios 🟣 costumam apontar para um [projeto](../projects/README.md): implemente lá.
4. Registre o que errou. Erros repetidos indicam um conceito a revisitar.
